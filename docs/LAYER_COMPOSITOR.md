# Editable scene layers

`SceneAppearance.layers` is the paint order from bottom to top. Layer IDs are unique within a scene; repeated kinds are supported. Each layer can store independent landscape and portrait frames, text, font size, color/alignment, fit mode, and camera framing. Frames use normalized canvas coordinates, with positions from -1 to 1 and dimensions from 0.02 to 2, allowing intentional cropping outside the canvas.

`getLayerFrame` supplies the same default boxes used by the compositor and editor. `StudioSession.getLayerBounds(orientation)` resolves active input dimensions for the editor. Screen/media inputs use contain fitting by default, preserving aspect ratio; camera inputs use cover fitting. A circular camera intentionally crops its input into a circle. Text sizes use logical pixels at a 1080-pixel output short edge and shrink to fit their boxes.

Live camera sources are horizontally mirrored in both output orientations, including scene captures and recorded canvases, so the presenter sees movement in the same direction. This is source metadata rather than a whole-canvas transform: shared displays, imported media, text, borders and the presentation fade keep their orientation. Additional cameras and camera replacement use the same path. Mirroring draws the camera once with a canvas transform and adds no intermediate video copy; a camera used as a screen layer is mirrored in its existing cached staging pass.

The workspace shows labeled 16:9 and 9:16 outputs with square, outlined boundaries against a separate matte. Both fit the available width and height, including their headers. Clicking a format header selects its orientation. Dragging snaps a layer's center or outer edges to the canvas within six CSS pixels; Alt/Option bypasses snapping, while arrow keys retain precise nudging. Guides, labels and selection handles are DOM overlays and never enter the recorded canvases. Canceling a drag restores that orientation's original explicit or automatic frame without changing the other orientation. Browser regressions live in tests/canvas-workspace.spec.ts.

Corner drags preserve the frame's starting width/height ratio by default, with a shared scale clamped to the size and origin limits and the opposite corner anchored. Shift permits independent width/height changes; the next drag uses the resulting ratio. Circular camera geometry stays circular. Side handles and keyboard nudging retain their existing axis-specific behavior.

A project's `sources` catalog owns camera, display and media identities. A scene layer's `sourceId` references one of those reusable inputs; the layer retains its own visibility, order, fit, shape and geometry. All standard camera layers reference the project's primary camera, and the default screen layers in **Câmera + tela** and **Apresentação** reference the same primary display. Layer IDs such as `screen` remain local to a scene and do not identify captures.

The source picker lists **Fontes do projeto**. Choosing a live existing source binds only the selected layer and does not open another browser chooser. Adding another screen, window, camera or file creates a new globally unique source identity, even when another source has the same kind. Reconnecting an offline source retains its ID; every layer referencing that ID receives the reconnected input. Binding a layer to a different existing source never changes its sibling bindings or geometry. A missing explicit source never silently substitutes another display.

`setLayerMediaSource(sourceId,file)` and `captureLayerScreen(sourceId)` update the identified session input. The display chooser opens from the explicit user gesture before asynchronous preparation. Source names, device choices, stored media references and scene bindings persist with the project. Browser display grants and live tracks do not persist: reopening a saved project never automatically opens a display chooser.

The registry survives scene switches and recording configuration changes. It pauses inactive video elements, gates audio from inactive captured displays, and preserves shared live captures while the project uses them. Removing or rebinding one scene layer must not release an input still referenced elsewhere. `removeLayerSource` releases the identified input's tracks and object URLs when ownership is removed. Leaving or switching projects disposes all captures from the previous project; unrelated projects never inherit its live streams. File video playback remains visual-only, matching the previous import behavior.

Microphone mute, gain and microphone device preferences belong to the scene appearance; camera device choices belong to their project source. The microphone graph is serial: source → raw analyser → scene mute/gain → output analyser → compressor/mix. Raw microphone energy remains measurable while mute produces zero output. It is an energy signal for a UI reminder, not speech recognition. Input replacement retains the other camera, microphone, display and media routes.

Countdowns start paused. Zero is a valid duration. Reset restores the configured duration and pauses; zeroing pauses at zero without changing the configured duration. Playing zero is a no-op. Editing the duration resets it in a paused state, while editing text or geometry preserves its current clock. Switching scene IDs can reset the timer through the application.

`CountdownPainter` supplies cached artwork and clock furniture. `SceneCompositor` uses it for editable title/timer layers and both output orientations. The presentation template places a large slide on the left and frames the presenter on the right in landscape. The slide's far edge tapers inward without rolling; shared projective coordinates drive axis-aligned image slices and the static scene card, with cached geometry and shadow. Slice density adapts to output size, limiting height changes between neighboring samples to 0.6 output pixels (with a minimum of 32 slices) so text and rules stay smooth without blurring. Portrait uses a flat, full-width slide above the camera, preserving the source aspect ratio up to 48% of output height (about 42% for 4:3 slides and 32% for 16:9). Explicit layer frames retain their independent geometry. Editor bounds use the presentation screen's dimensions for the same source-aware split as recorded output.

Live video is copied once per visible screen crop into a canvas bounded by the output's long edge. Both orientations reuse that snapshot through a shared render-frame ID; the perspective slices sample the stable canvas instead of repeatedly converting or reading back the captured video. Crops, source replacement, transparency, and standalone thumbnail refreshes retain independent state. Live output and staging contexts allow browser acceleration rather than requesting CPU-backed canvases. Screen-capture requests and retained tracks are bounded to the selected recording dimensions and frame rate, with a guarded fallback when the browser cannot apply scaling.

The optional `cameraFade` scene setting defaults on for presentation scenes, and each camera can override it explicitly, including false. Horizontal rectangular/rounded presentation cameras paint one cached background-colored gradient across their leftmost 22%, inside the camera clip and below any explicit border. Static scene cards use the same stops. Portrait, circular cameras, and other layouts are unaffected. `tests/camera-fade.test.mjs` checks the actual pixel transition, preserved presenter colors, overrides, and portrait output; project-store tests check defaults and reload persistence.

While a live screen is visible, idle preview backing canvases are capped at 720p and 30 fps. The selected recording size and capture settings are preserved. Starting recording restores both full-size canvases and paints a complete frame before creating either capture stream. Recording and finalization lock those dimensions until the output tracks have closed, then the lighter preview resumes. `tests/live-screen.test.mjs` exercises actual video-element input, per-frame snapshot reuse, source/crop isolation, capture bounds, and decoded full-resolution output across this transition.

Validation lives in `tests/layer-engine.test.mjs` and `tests/scene-compositor.test.mjs`. It includes independent image/screen ownership, source survival across prepare, camera-less media recording, true per-layer text rendering, contain aspect ratios, partial-background clearing, timer pause/reset/zero behavior, per-scene gain, and decoded PCM checks proving that raw metering does not bypass mute. Performance fixtures target 30 fps and should run with controlled, serial browser workloads; sustained 1080p/4K recording remains a separate qualification.

`tests/shared-sources.spec.ts` exercises actual rendered display pixels across the standard scene templates, explicit second captures, existing-source selection without new chooser calls, reference lifetime, project cleanup, and reconnecting saved source identities after reload. It uses ordinary camera mode with controlled display streams rather than synthetic source fallbacks.
